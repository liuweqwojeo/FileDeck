# FileDeck v0.1.2 构建 7 发布说明

日期：2026-10-25。适用 macOS 14+、Apple Silicon，开发预览版；发布标签 `v0.1.2-build7`。准确源码入口随安装包的 `SOURCE-CODE.md` 提供。

## 变更与影响

- R4：编辑资源清单升级为 schema 2，绑定源码、构建脚本、package.json、依赖锁与产物摘要；发布构建从锁安装依赖并只读重建比较，拒绝旧资源。
- R5：普通打包与 package-only 统一校验源包和最终暂存包，覆盖 Office 资源、模板、内核/Hunspell/辅助程序 ARM64、本地编辑器、构建身份和严格签名；失败保留原发布应用。
- 保留构建 6 的 JPEG 保存保真、WebKit 已同步草稿恢复和目录改名路径同步。

## 数据库、配置及接口

数据库变更、初始化 SQL、升级 SQL、回滚 SQL：无。Redis、MQ、中间件部署、对外 API、错误码变更：无。用户配置和文档无需迁移，bundle ID 保持 `local.fileworkbench.desktop`。

清单升级只影响开发构建/校验，应用运行不需要 Node/npm/Python。历史 schema 1 包仍可运行；使用新版打包器时需要先重建编辑资源和原生应用。检查历史包应使用对应源码版本的工具。

## 安装及验证

1. 从本次 Release 下载 ZIP 和 SHA256SUMS.txt，在同一目录执行 `shasum -a 256 -c SHA256SUMS.txt`。
2. 保存文档并正常退出旧应用，解压并用完整 FileDeck.app 替换“应用程序”中的旧版。
3. 启动后核对版本 0.1.2、构建 7，检查目录浏览与文档保存。

本机重新从依赖锁安装后，通过编辑资源只读比较、23 项 Node 测试和 155 项 Python 构建工具测试。原生应用重新构建，并通过新源包/暂存包校验。真实副本中分别删除编辑脚本、Office 模板和内核，均被拦截且原目标保持原样；完整资源正常打包成功。

安装后的完整文件清单与构建产物一致，并通过新版静态检查及隔离、禁网的 Office 三格式和混合工作台运行验收。分发 ZIP 另行检查 CRC、解压完整性、签名与远程附件摘要。详细依据见[审查文档](code-review-and-roadmap.md)。

## 风险及边界

构建配置为 Debug，使用临时签名，尚未完成 Developer ID 签名及 Apple 公证。静态门禁不证明任意 Office 文档兼容性，也不完整模拟动态库相对路径解析。

本轮运行资源 JS/CSS/HTML 和许可文件字节与构建 6 一致；系统输入法组合输入、复杂文档、首次授权、拔盘及其他机器仍需专项验收。WebKit 恢复仅覆盖存活会话中已同步的内存草稿，不包含应用崩溃或机器重启后的持久恢复。

## 回退与清理

发布成功后按用户要求将本机旧应用副本移入废纸篓，保留当前构建 7 和必要分发验证产物，不清理用户文档或偏好。

需要回退时，从[构建 6 Release](https://github.com/liuweqwojeo/FileDeck/releases/tag/v0.1.2-build6)下载旧 ZIP 与配套校验文件，校验后保存文档、正常退出构建 7，替换应用并启动核对构建号 6。应用回退不撤销已保存内容和目录改名，无 SQL/配置/中间件回滚脚本。

## 发布检查

修复提交与发布标签必须指向实际验收源码；上传的 ZIP 大小、SHA-256 与校验文件一致后才公开 Release。README 登记准确源码、构建号、下载地址、体积与校验值。缺依赖、资源过期、丢文件、错误架构/身份或签名失败均阻止打包发布。
