# FileDeck v0.1.2 构建 8 发布说明

日期：2026-10-25。适用 macOS 14+、Apple Silicon；开发预览版，发布标签 `v0.1.2-build8`。准确源码提交随安装包的 `SOURCE-CODE.md` 提供。

## 变更与影响

- R6：PDF/图片变换结果在替换编辑缓冲区前检查 256 MiB 上限；PDF 合并、追加图片和图片新建 PDF 采用累计输入预算。拒绝超限时保留原内容、保存基线及撤销/重做历史。
- R7：查找、撤销、重做按真实文档能力、历史、只读和忙碌状态启用；CSV、图片和 Quick Look 的未实现查找禁用。
- 系统另存：用户明确选择已删除的原路径时允许重建；普通保存及已存在的外部修改仍受保护。回归通过外部 Accessibility 按真实系统保存按钮，验证系统回调与落盘，不以本进程键盘投递或模拟完成替代。
- 保留构建 6 的 JPEG 保真、存活会话已同步草稿恢复、目录路径同步，以及构建 7 的编辑资源和打包门禁。

## 数据库、配置和接口

数据库变更、初始化 SQL、升级 SQL、回滚 SQL：无。配置迁移、Redis、MQ、中间件、对外 API 和错误码变更：无。用户文档无需迁移，bundle ID 仍为 `local.fileworkbench.desktop`。

Accessibility 仅用于开发者主动运行的独立系统面板验收助手，应用日常运行无需此权限，也不需要 Node/npm/Python。测试助手拒绝错误令牌及不匹配的进程、面板或文件名；没有权限时失败，不静默跳过验收。

## 安装与验收

1. 下载本次 Release 的 ZIP 与 `SHA256SUMS.txt`，在同一目录执行 `shasum -a 256 -c SHA256SUMS.txt`。
2. 保存文档并正常退出旧版，用解压后的完整 `FileDeck.app` 替换“应用程序”中的应用。
3. 启动核对版本 0.1.2、构建 8；检查文件浏览、编辑保存，以及适用文档的菜单状态。

本轮从依赖锁重新安装后，通过编辑资源只读重建比较、23 项 Node 测试、155 项 Python 构建工具测试、146 项 Swift 测试与 11 组真实媒体/CSV 会话回归。完整真实文档回归 45 项断言通过，包含真实系统另存按钮确认、目标 URL/实际字节/关闭状态、草稿恢复、外部冲突和菜单能力。具体原生构建、本机安装与最终分发验收见[审查文档](code-review-and-roadmap.md)。

构建 8 已安装至 `/Applications/FileDeck.app`，全清单、架构/资源/严格签名及禁网运行通过；真实恢复草稿面板取消和保存均由外部 AX 实际完成，驱动及独立文件复核通过，进程退出 0。原文件、完整草稿、保存路径、dirty 清除及对象释放均有对应断言。

## 风险及边界

采用 Debug 配置和临时签名，尚未完成 Developer ID 签名及 Apple 公证。PDF 输入预算采用保守的累计压缩字节上限，不是 PDFKit/ImageIO 解码、序列化和撤销历史的进程总内存上限；超过 256 MiB 的实机压力仍未验证。

WebKit 故障通过公开终止委托注入，恢复范围是存活会话中已同步的草稿，不包含未同步的最后输入、应用崩溃或重启后的持久恢复。复杂 Office 文档、系统输入法组合输入、首次授权、拔盘及其他机器仍需专项验收。

## 回退与清理

需要回退时，从[构建 7 Release](https://github.com/liuweqwojeo/FileDeck/releases/tag/v0.1.2-build7)下载旧 ZIP 和配套校验文件；校验后保存文档、正常退出构建 8，替换应用并核对构建号 7。回退应用不撤销已经保存的文档或文件操作，无 SQL、配置或中间件回滚脚本。

发布通过后按用户要求将本机旧应用副本移入废纸篓；保留当前构建 8 及历史 ZIP，不清理用户文档和偏好。

## 发布检查

源码与验收摘要一致后提交并打标签；最终包及已安装副本分别检查资源、架构和严格签名，并运行隔离、禁网的 Office 与混合工作台验收。系统恢复草稿面板需由外部操作者实际取消一次、保存一次。ZIP 检查 CRC、解压清单与内容，再核对远程附件大小和 SHA-256 后公开，README 登记准确下载信息。
